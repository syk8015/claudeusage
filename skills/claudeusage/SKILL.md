# 구독 본전 계산기

Claude 구독료를 제대로 뽑고 있는지 로컬 기록으로 재는 도구 모음이다.

## 먼저 알아야 할 것

구독은 토큰당 과금이 아니다. **진짜 제약은 달러가 아니라 한도 게이지다.** 그래서 "얼마 썼나"보다 "한도가 왜 닳았나", "그 대가로 무엇이 남았나"를 본다.

세 가지가 이 도구의 답이다. 사용자에게 설명할 때 이 틀을 쓴다.

1. **돈 아끼는 요령과 한도 아끼는 요령이 다르다.** 캐시 읽기는 비용의 대부분이지만 한도 무게는 신규입력의 약 1/70이다.
2. **낭비는 실수보다 대화 길이에서 나온다.** 재작업·실패·거부를 다 합쳐 4.1%인데, 대화가 길어져서 나가는 돈은 12.3%다. "실수를 줄이세요"가 아니라 **"대화를 자주 끊으세요"**가 맞는 조언이다.
3. **채팅도 같은 한도를 먹는다.** claude.ai 채팅·앱 사용은 로컬 기록에 안 남아서, 로그만 읽는 도구는 소진을 덜 센다.

## 어느 것을 부를까

| 사용자가 묻는 것 | 부를 것 |
|---|---|
| 지금 한도 얼마 남았나 | `current_limits` |
| 한도가 왜 이렇게 빨리 닳나 | `limit_breakdown` (view=windows, 이유를 더 캐면 fit) |
| 채팅이 한도를 얼마나 먹나 | `chat_share` (view=weeks) |
| 구독 본전 뽑나 / 뭐가 남았나 | `subscription_value` (view=summary) |
| 어디서 낭비하나 | `subscription_value` (view=waste) |
| 돈이 어느 작업에 갔나 | `subscription_value` (view=mix) |

MCP 서버(`claudeusage`)가 붙어 있으면 그 도구들을 부른다. 없으면 같은 것을 CLI 로 돌린다.

```bash
python3 __REPO__/tools/cc-usage.py          # 지금 한도 + 제품별 분해
python3 __REPO__/tools/cc-limit.py          # 창별 한도 소진
python3 __REPO__/tools/cc-limit.py --fit    # 한도 가중치·모델 배율
python3 __REPO__/tools/cc-chat.py           # 채팅이 먹은 한도
python3 __REPO__/tools/cc-value.py --all    # 살아남은 줄·비용
python3 __REPO__/tools/cc-value.py --project <경로> --waste
```

## 숫자를 읽어 줄 때 지킬 것

- **배수를 말할 때는 분모를 밝힌다.** 같은 데이터로 Fable 5.1이 토큰당 3.9배, 달러당 5.7배로 나온다. 달러당은 세션 스타일(대화를 얼마나 길게 끄는가)이 섞여 모델 가중치가 아니다.
- **"$528 아꼈다"고 말하지 않는다.** API 환산가는 "종량제였다면 나왔을 돈"이지 절약액이 아니다. 종량제였다면 압축하고 짧게 끊었을 것이므로 구조적으로 부풀어 있다.
- **채팅 몫은 추정과 정답을 구분해 말한다.** `chat_share` 의 주간 표에서 "정답" 칸은 앤트로픽 엔드포인트가 준 값이고, 나머지는 뺄셈 추정이다. 정답 칸이 비어 있으면 `current_limits` 에 `record=true` 로 표본을 남기라고 권한다 — 주간 창이 지나가면 그 주 정답은 다시 못 받는다.
- **표본이 얇으면 얇다고 말한다.** 창 수가 5개 미만인 모델 배율, 온전한 창이 몇 개뿐인 주는 방향만 말한다.

## 흔한 물음에 바로 쓰는 답

- **"한도 아끼려면?"** — 대화를 자주 끊는다(컨텍스트 비대가 가장 큰 낭비). 같은 일이면 가벼운 모델을 쓴다(Fable 5.1은 Opus 5보다 출력 토큰당 약 3.9배 빨리 닳는다). 긴 출력을 줄인다(출력 토큰 무게가 가장 크다).
- **"왜 어제보다 빨리 닳지?"** — `limit_breakdown` 으로 창별 $/1%p 를 본다. 창마다 10배까지 차이 난다. 그다음 `chat_share --windows` 로 그 시간대에 채팅 몫이 컸는지 본다.
- **"내가 잘 쓰고 있나?"** — `subscription_value` 의 살아남은 줄 비율과 낭비 비중을 같이 말한다. 편집의 68%가 살아남는 것이 이 계정의 기준선이다.
